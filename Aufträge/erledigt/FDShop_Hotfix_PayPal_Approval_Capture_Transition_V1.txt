1. NEUER REALBEFUND
======================================================================

Der COOP-Fehler wurde real identifiziert und behoben:

Joomla System – HTTP Headers:
Cross-Origin-Opener-Policy
same-origin -> same-origin-allow-popups

Danach funktioniert der echte PayPal-Sandbox-Buyer-Login aus FDShop.

Realer Test auf IONOS:

- FDShop Checkout 0,50 EUR
- PayPal Sandbox
- Create Order erfolgreich
- PayPal Order-ID:
  9AF35683BN788635J
- PayPal API:
  POST /v2/checkout/orders -> HTTP 201
- Orderstatus nach Create:
  CREATED
- Buyer-Login erscheint
- Sandbox Personal Buyer meldet sich an
- Buyer bestätigt die Zahlung
- Rückkehr zu FDShop erfolgt
- FDShop zeigt:
  „PayPal konnte die Zahlung nicht abschließen. Ihr Warenkorb bleibt erhalten.“
- KEINE FDShop-Bestellung erzeugt
- Warenkorb bleibt erhalten
- Reservierung bleibt zunächst bestehen

Entscheidender PayPal-Event-Log-Befund:

Für Order 9AF35683BN788635J existiert KEIN:
POST /v2/checkout/orders/{ORDER-ID}/capture

Damit wurde PayPal serverseitig überhaupt nicht zum Capture aufgerufen.

Der Fehler liegt daher vor dem tatsächlichen PayPal-Capture-API-Request:
zwischen erfolgreicher Buyer-Freigabe / SDK-Rückgabe und dem Aufruf des
FDShop-Endpunkts payment.capture bzw. dessen Übergang zum PayPalClient.
