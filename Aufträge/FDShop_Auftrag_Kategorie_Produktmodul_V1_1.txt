1. REAL GEFUNDENER FEHLER – MODUL OHNE GELADENE FDSHOP-KOMPONENTE
=====================================================================

Auf IONOS funktioniert das Modul auf Seiten, auf denen `com_fdshop` selbst gerendert/geladen wird, z.B. Kategorie- und Produktansichten.

Auf der Startseite befindet sich dagegen keine FDShop-Komponentenansicht. Dort führt das Modul aktuell zu einem fatalen Joomla-Fehler:

0 There is no "com_fdshop.site" asset of a "style" type in the registry.

Der Call Stack führt zum Modul und dessen Verwendung von:
- `com_fdshop.site`
- sowie den weiteren FDShop-WebAssets.

Im aktuellen Modulcode wird sinngemäß:
`useStyle('com_fdshop.site')->useScript('com_fdshop.purchase')->useScript('com_fdshop.products-module')`
aufgerufen.

Die Assetdefinitionen existieren bereits zentral in `media/joomla.asset.json`.

URSACHE / ZIELRICHTUNG
Das eigenständige Site-Modul darf nicht voraussetzen, dass `com_fdshop` vorher als aktive Seitenkomponente gelaufen ist und dadurch deren WebAsset-Registry bereits bekannt ist.

Das Modul ist gerade für Startseite und andere Joomla-Seiten außerhalb einer FDShop-Komponentenansicht vorgesehen.

Saubere Joomla-6-konforme Lösung:
- vorhandene zentrale FDShop-WebAsset-Definition weiterhin als Single Source verwenden,
- benötigte Registry/Assetdefinition vor `useStyle()/useScript()` sicher verfügbar machen,
- keine Kopie von site.css/purchase.js/products-module.js in das Modul,
- keine zweite Assetdefinition, die langfristig auseinanderlaufen kann,
- keine Abhängigkeit von zufälliger Renderreihenfolge anderer FDShop-Erweiterungen.

Die genaue Joomla-6-konforme Registrierung anhand des aktuellen Codes selbst bestimmen.

ABNAHME ASSET
Mindestens real in Sandbox prüfen:
A. Seite mit aktiver `com_fdshop`-Kategorie/Produktansicht + Modul → funktioniert.
B. normale Joomla-Seite/Startseite OHNE aktive FDShop-Komponentenansicht + Modul → funktioniert.
C. benötigtes CSS und JS wird geladen.
D. keine doppelte/fehlerhafte Assetregistrierung.
E. mehrere Modulinstanzen auf derselben Nicht-FDShop-Seite funktionieren.
F. Purchase Action funktioniert dort ebenfalls.
G. keine PHP-/Joomla-/JS-Fehler.

Dieser Punkt ist der wichtigste Bugfix des Auftrags.

2. MODULHEADER – NEUE ANORDNUNG
=====================================================================

Die Kopfzeile über dem Produktkarussell soll künftig in EINER gemeinsamen Zeile aufgebaut sein.

Gewünschtes Desktopprinzip:

[Titel] [Zur Kategorie]                                  [‹] [›]
[                    Produktkarussell                         ]

Links:
1. Modultitel
2. mit leichtem Abstand direkt dahinter ggf. Button „Zur Kategorie“

Rechts:
3. Carousel-Navigation, sofern für die konkrete Instanz erforderlich.

Die Navigation soll NICHT mehr in einer eigenen Zeile unterhalb des Karussells stehen.

ANFORDERUNGEN
- Titel links.
- Kategoriebutton direkt nach Titel, nicht an den rechten Rand.
- kleiner optisch sauberer Abstand zwischen Titel und Button.
- Carousel-Navigation ganz rechts.
- Navigation bleibt an dieser Position auch dann, wenn kein Kategoriebutton angezeigt wird.
- Navigation nur anzeigen, wenn sie fachlich benötigt wird (bestehende Carousel-/Produktanzahlregel beibehalten).
- Grid-Modus ohne Carousel benötigt keine Carouselnavigation.
- responsive Verhalten sinnvoll; auf sehr kleinen Breiten darf die Kopfzeile sauber umbrechen, ohne Überlagerung.
- keine starre Pixelkonstruktion.
- bestehende FDShop-CI respektieren.

NAVIGATIONSDESIGN
Carousel-Navigationsbuttons:
- Hintergrund schwarz,
- Pfeile weiß,
- kompakte Form passend zum Modul,
- sinnvoller Hover-/Focuszustand,
- zugängliche aria-labels beibehalten,
- keine externe Iconbibliothek nur dafür einführen.

3. NEUE ADMINOPTION „LINK-KATEGORIE“
=====================================================================

Die bisherige einfache Option für den Kategoriebutton soll zu einer dreistufigen Einstellung weiterentwickelt werden.

Eigene Admin-Zeile / Feldbezeichnung:

„Link-Kategorie“

Dropdown mit exakt folgenden fachlichen Varianten:

1. „Kein“
2. „Titel + Button“
3. „Nur Titel“

FACHLICHE WIRKUNG

A) KEIN
- Modultitel ist normaler Text, KEIN Link.
- Button „Zur Kategorie“ wird NICHT ausgegeben.
- Carouselnavigation bleibt davon unberührt und weiterhin rechts, sofern benötigt.

B) TITEL + BUTTON
- Modultitel ist Link zur aktuell gewählten FDShop-Kategorie.
- Button „Zur Kategorie“ wird ebenfalls angezeigt und verlinkt auf dieselbe Kategorie.
- Carouselnavigation bleibt rechts.

C) NUR TITEL
- Modultitel ist Link zur aktuell gewählten FDShop-Kategorie.
- Button „Zur Kategorie“ wird NICHT ausgegeben.
- Carouselnavigation bleibt rechts.

ROUTING
Titel und Button müssen denselben vorhandenen FDShop/Joomla-Router für die Kategorie verwenden.
Keine manuell zusammengesetzten nicht-SEF-fähigen URLs.

BUTTONTEXT
Die bestehende Konfiguration für den Buttontext („Zur Kategorie“) bleibt erhalten.

Sie ist nur relevant/sichtbar, wenn die Einstellung „Titel + Button“ gewählt ist.
Joomla-`showon` oder gleichwertige saubere Formlogik verwenden, sofern passend.

=====================================================================
5. MODULTITEL / JOOMLA SHOWTITLE
=====================================================================

Aktuellen Zusammenhang mit Joomla-`showtitle` ausdrücklich analysieren.

Im aktuellen Modul-Template wird der Titel selbst ausgegeben, wenn `module->showtitle === 0`. Das kann bewusst dazu dienen, doppelte Ausgabe über Joomla-Modul-Chrome zu vermeiden.

Mit dem neuen verlinkbaren Titel im gemeinsamen Modulheader muss gelten:
- Titel genau einmal sichtbar,
- keine doppelte Joomla-Chrome- plus FDShop-Titelausgabe,
- Link-Kategorie kann den tatsächlich im FDShop-Header dargestellten Titel verlinken,
- Modul bleibt in normalen Joomla-Modulpositionen verwendbar.

Keine globale Template-/Chrome-Neuentwicklung.

Wenn die aktuelle `showtitle`-Semantik bewusst erforderlich ist, sauber fortführen und testen. Falls sie korrigiert werden muss, nur scope-konform.
